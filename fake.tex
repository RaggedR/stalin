\begin{abstract}
\noindent
Ghani's containers turn on a dependent function: the type of the reply depends
on the prompt. TypeScript has no dependent types. This note is about the one
substitution that makes the whole edifice stand --- a generic method whose
return type is a conditional type applied to the inferred type argument ---
what it genuinely buys, exactly where it degrades, and the one place the
project abandons it altogether. Along the way it disposes of a natural
suspicion: that \texttt{async} had something to do with it. It did not.
\end{abstract}

\section{The thing to be faked}

An inhabitant of a container $(P, R)$ is a dependent function
\[
  (p : P) \to R\,p
\]
in which the \emph{type} of the result is computed from the \emph{value} of the
argument. Ask for a harvest and you get a harvest report; ask for a census and
you get a census return; and no type in the language relates the two except
through $p$ itself.

TypeScript has no such construct. What it has is: generic functions, which
infer a type argument from a value argument; and conditional types, which
compute a type from a type. Put together they give this:

\begin{lstlisting}
run<S extends Shape<C>>(shape: S): PosAt<C, S>
\end{lstlisting}

\noindent Three ingredients, and it is worth being precise about which does
what.

\begin{center}
\footnotesize
\begin{tabular}{@{}lp{0.68\textwidth}@{}}
\toprule
\textbf{generic inference} & \texttt{S} is recovered from the argument --- this is
the only channel by which anything about $p$ reaches the type level \\
\textbf{conditional type} & \texttt{PosAt<C, S>} computes the position type from
\texttt{S}, by distributing over the union of fibres \\
\textbf{a finite index} & makes that distribution \emph{exact}: over a finite $S$,
$\Sigma\,(s : S).\,B\,s = \bigcup_{s} \{s\} \times B\,s$ \\
\bottomrule
\end{tabular}
\end{center}

\section{\texttt{async} has nothing to do with it}

The real signature carries a \texttt{Promise}, which invites the thought that
concurrency is somehow load-bearing. It is not. Here is the same encoding with
no \texttt{Promise}, no \texttt{await}, and no socket:

\begin{lstlisting}
interface SyncRunner<C extends Cont> {
  readonly fibres?: C;
  run<S extends Shape<C>>(shape: S): PosAt<C, S>;    // no Promise
}
declare const agri: SyncRunner<Agri>;

const h = agri.run({tag: "Harvest", year: 1930});
const c = agri.run({tag: "Census"});
const grain: number = h.grain;        // typed HarvestReport, uncast
const hands: number = c.workforce;    // typed CensusReturn,  uncast
// @ts-expect-error   a Census reply has no `grain`
const wrong: number = c.grain;
\end{lstlisting}

\noindent That file typechecks with zero errors, and the negative assertion
fires --- TypeScript reports an unused \texttt{@ts-expect-error} as an error in
its own right, so its silence is evidence that the dependency really bites.

\note{So why is the real thing \texttt{async}?} Because the reply arrives from
another process over a socket. Causation runs the other way from the suspicion:
we chose real process boundaries, and \emph{that} forced \texttt{Promise}.
Ghani's own point in \S3 is that what makes a program event-driven is the
prompt-indexed response type, not the event loop --- strip the waiting away and
the container is what remains.

\note{One thing \texttt{async} does buy.} It makes $\boxtimes$ against $\lhd$
visible in the \emph{execution} and not only in the types. The tensor fires
both prompts at once and requires both replies; the sequential composition
cannot even construct its second prompt until the first reply is in hand:

\begin{lstlisting}
const [l, r]  = await Promise.all([a.run(s.left, d), b.run(s.right, d)]);  // (x)
const first   = await a.run(s.first, d);
const second  = await b.run(s.next(first), d);                            //  <|
\end{lstlisting}

\noindent Synchronously these would be two calls in a row either way, and the
difference would live entirely in the types.

\note{A correction.} The source comment on that \texttt{Promise.all} says it
``is not an optimisation here; it is the definition''. That is an overstatement,
and writing a synchronous tower disproves it. The tensor is defined by both
shapes being supplied \emph{up front} and both replies being owed --- and that
independence is enforced by the shape type $\{\texttt{left}: S_A,\ \texttt{right}:
S_B\}$, not by concurrency. You cannot make the right prompt depend on the left
reply, because you had to construct it before calling \texttt{run}.
\texttt{Promise.all} adds parallelism, not meaning.

\subsection*{So it could have been synchronous --- and here it is}

\texttt{sync-tower.ts} is the same construction with no \texttt{async},
\texttt{await} or \texttt{Promise} anywhere in the algebra. A hop blocks:

\begin{lstlisting}
new Deno.Command("deno", {args: [...delegate...], stdout: "piped"}).outputSync()
\end{lstlisting}

\noindent It runs a tensor over two live commissariats and returns typed,
uncast positions. This inverts how the architecture looks. Deno has no
synchronous \texttt{fetch} and no synchronous HTTP client at all, so an
\emph{in-process} tower would have had no choice but to be async. It is
precisely because a hop is a spawned CLI tool that the algebra can block: the
child does the asynchronous fetch inside its own event loop, and the parent
simply waits. The decision that looks more distributed is the one that made
synchrony available.

What cannot be synchronous is the \emph{listening} side --- \texttt{Deno.serve}
handlers are async and there is no blocking HTTP server. But that is outside
the algebra, and the line falls exactly where \S3 says it should:
\textbf{the container algebra can be synchronous; the event loop cannot.}

\section{Where the dependency is exact}

The substitution works when the compiler can see \emph{which fibre} a prompt
lies in. Two cases, both verified:

\begin{lstlisting}
const a = agri.run({tag: "Harvest", year: 1930});      // S = the literal shape
                                                       // -> {grain: number}   EXACT

const p: Shape<Agri> = {tag: "Harvest", year: 1930};   // declared as the union...
const b = agri.run(p);                                 // ...but narrowed by the
                                                       // discriminant -> EXACT
\end{lstlisting}

\noindent The second was a surprise. A \texttt{const} declared at the union
type but initialised with a literal is narrowed by its discriminant tag, so the
dependency survives being written down as a variable. The encoding is more
robust than it looks.

\subsection*{The introduction rules do the real work}

Each combinator ships a constructor for its shapes, and each is generic in the
fibre. That is what keeps \texttt{S} narrow through a composite. The sequential
one is the deepest instance:

\begin{lstlisting}
step<SA extends Shape<A>, SB extends Shape<B>>(
  first: SA,
  next: (r: PosAt<A, SA>) => SB,
): {first: SA; next: (r: PosAt<A, SA>) => SB}
\end{lstlisting}

\noindent \texttt{SA} is inferred from \texttt{first}, so \texttt{next} is
contextually typed at \emph{that fibre alone}: it receives the positions of the
shape you actually gave, not a union over all of them. This is the $\Sigma$-type
faked --- not a pair of prompts, but a prompt together with a function from its
replies to the next prompt. And it is why, in the game,
\texttt{supplied.first.toPort} is a \texttt{HaulReport} field with no cast at
the call site.

\section{Where it degrades}

The fake carries the dependency on the \textbf{static type} of the argument,
never on its runtime value. So it fails precisely where the compiler cannot see
a single fibre --- and the commonest such place is a \emph{forwarder}: any
helper generic over the container's prompts.

\begin{lstlisting}
function forward(shape: Shape<Agri>) {
  return agri.run(shape);          // S is now the WHOLE union
}
const c = forward({tag: "Harvest", year: 1930});
// c : {grain: number} | {workforce: number}      <-- the dependency is gone
\end{lstlisting}

\noindent \texttt{PosAt} distributes over \texttt{S} as well as over \texttt{C},
so a union argument yields the union of \emph{all} positions. Note what this is
and is not. It is not unsound --- you cannot read \texttt{grain} off it without
narrowing first, and the compiler will stop you. But the dependency has been
traded for a disjunction, and the caller must re-discover by hand what the type
system knew one frame earlier.

\note{This is the precise sense in which it is a fake.} A genuine
$(p : P) \to R\,p$ returns $R\,p$ for the actual runtime $p$, always, including
inside a forwarder. This returns the exact position only where the compiler
statically knows the fibre, and the union everywhere else. The dependency is on
the singleton type TypeScript infers, not on the value.

\section{Where it is abandoned}

At the outermost edge the project gives up on it entirely. Everything a human
or a search program sends to the Plan goes through:

\begin{lstlisting}
export async function ask(prompt: unknown): Promise<Dict>
\end{lstlisting}

\noindent \texttt{unknown} in, \texttt{Record<string, unknown>} out. Not a
degraded dependency --- no typing at all.

This is not laziness, and it is worth saying why. An interactive menu is a
forwarder by construction: it holds a list of options the player might choose,
it does not know which until a key is pressed, and a list of ten differently
typed prompts is exactly the union case above. The same is true of the letter
search, which replays arbitrary sequences. So the container discipline holds
\emph{inside} the tower, where Gosplan composes and calls its commissariats
through \texttt{leaf} and the combinators, and stops at the boundary where
prompts become data chosen at runtime.

\note{Which is the honest shape of the result.} Dependent typing survives
exactly as far as the compiler can follow the control flow, and no further. The
tower's interior is typed; its front door is not.

\section{The rest of the fakery, briefly}

\textbf{The container as its graph.} $R$ cannot be a function from values to
types, so a container is presented as the union of its fibres, one \texttt{Fib}
per prompt. \texttt{Fib} is never constructed --- it is a type-level record, the
object language of $\mathrm{Fam}(\mathrm{Set}^{\mathrm{op}})$, taken apart only
by \texttt{infer}.

\textbf{The delegate leg as a CLI tool.} $u : P \to Q$ is not a function call
but a spawned process, \texttt{delegate.ts <port> <json> <depth>}, which knows
nothing of any container: it carries text. Control genuinely leaves the process.
The file is located by \texttt{new URL("./delegate.ts", import.meta.url)},
resolved at run time and never checked --- which is how a clean typecheck once
produced a playthrough that died on its first hop.

\textbf{The wire.} JSON has six kinds of value and no notion of types, so a tag
is a claim rather than a fact, and a wrong one usually does not crash: a missing
property reads as \texttt{undefined}, so the handler returns HTTP 200 with a
well-formed reply meaning nothing. Both directions are therefore validated
rather than cast --- 56 field checks across the five servers, and per-fibre
decoders on the way back.

\noindent Every \texttt{run} body must destructure a shape it knows only
through a conditional type and re-assert the result; hence two per combinator.
\textbf{None is in the game.} The game's own casts are \texttt{as const} on
literals and narrowing strings a validator has already checked; no call site in
\texttt{stalin} ever asserts the type of a container position.

\subsection*{Two traps, both silent}

\textbf{The fibre test written backwards.} \texttt{Extract<C, Fib<S, unknown>>}
keeps the fibres assignable \emph{to} the query, but a shape you hold is usually
\emph{narrower} than its fibre's declared shape. What is wanted is
\texttt{S extends S1}. Written the other way, every position becomes
\texttt{never} and nothing complains near the mistake.

\textbf{Conditional types are not inference sites.} If \texttt{C} occurs only
inside \texttt{Shape<C>} and \texttt{PosAt<C, S>}, TypeScript cannot infer it:
\texttt{seqC(a, b)} silently infers \texttt{A = Cont} and every downstream
position becomes \texttt{unknown}. Hence the phantom \texttt{readonly fibres?: C},
a field that is never assigned and exists solely to give \texttt{C} an inferable
position.
